Hướng dẫn Monitoring — shopcaovanson

Prometheus + Grafana trên Kubernetes: truy cập, đọc dashboard, debug CrashLoop/OOM, và xử lý khi chính hệ thống monitor bị lỗi.

Grafana: monitor.shopcaovanson.xyz Namespace: monitoring VPS: 110.172.29.72 Overlay: dev (16GB)

1. Tổng quan kiến trúc

Bạn (trình duyệt) │ ├─ https://monitor.shopcaovanson.xyz → Ingress nginx → Grafana │ │ │ └─ đọc metrics từ Prometheus │ └─ (admin) SSH + port-forward :9090 → Prometheus UI Prometheus thu thập: • node-exporter → CPU/RAM/disk của VPS (node) • kube-state-metrics → trạng thái Deployment/Pod/PVC • cAdvisor (kubelet) → CPU/RAM từng container • (tuỳ chọn) metrics app nếu service expose /metrics Namespaces quan trọng: shop → api-gateway, auth, product, order, frontend... infra → postgres, kafka, redis, mongo, ES, minio, zookeeper monitoring → grafana, prometheus, operator, node-exporter
Khi nào dùng cái gì?
  • Grafana — theo dõi hàng ngày, biểu đồ, tìm pod ăn RAM.
  • kubectl — debug nhanh khi pod CrashLoop / deploy fail.
  • Prometheus UI — query PromQL chi tiết (admin).
  • Scripts — diagnose-apps.sh, diagnose-infra.sh, verify-app.sh.

3.3 Cách đọc dashboard Namespace Pods

  1. Mở Namespace (Pods).
  2. Góc trên chọn namespace = shop.
  3. Xem panel Memory Usage / CPU Usage — cột cao bất thường = nghi ngờ OOM hoặc leak.
  4. Đổi namespace = infra để xem postgres, kafka, elasticsearch (thường nặng nhất).
  5. Time range góc phải: Last 15 minutes khi debug live; Last 24 hours khi tìm spike ban đêm.

4. Cách dùng Prometheus UI

Prometheus không expose ra internet (chỉ ClusterIP). Phải port-forward + (nếu từ máy Windows) SSH tunnel.

4.1 Từ máy Windows (1 lệnh)

SSH + port-forward gộp
ssh -L 9090:127.0.0.1:9090 root@110.172.29.72 "kubectl port-forward -n monitoring svc/kube-prometheus-stack-prometheus 9090:9090"

Giữ cửa sổ mở → trình duyệt: http://localhost:9090

4.2 Hai terminal (nếu thích)

VPS:

kubectl port-forward -n monitoring svc/kube-prometheus-stack-prometheus 9090:9090

Windows:

ssh -L 9090:127.0.0.1:9090 root@110.172.29.72
Lỗi channel N: open failed: connect failed: Connection refused
Nghĩa là trên VPS không có gì listen 127.0.0.1:9090 — thường vì quên chạy kubectl port-forward, hoặc session port-forward đã tắt. Chạy lại port-forward rồi tunnel.

4.3 Trong Prometheus UI

  • Graph — nhập query → Execute → xem biểu đồ.
  • Status → Targets — target nào UP/DOWN (scrape fail).
  • Status → TSDB Status — dung lượng metric lưu (retention ~5 ngày trên VPS này).

6. Checklist hàng ngày (5–10 phút)

  1. Mở Grafana → Cluster / Node: RAM < ~85%, disk còn trống.
  2. kubectl get pods -n shop — không CrashLoopBackOff / ImagePullBackOff.
  3. kubectl get pods -n infra — postgres, kafka, redis, ES Running.
  4. Mở site: https://shopcaovanson.xyz và API https://vocabee.cloud.
  5. Sau mỗi deploy CI: xem job GitHub Actions xanh; nếu đỏ đọc bước migrate/deploy.
VPS 16GB: luôn ưu tiên theo dõi infra (ES + Kafka + Postgres) vì chiếm RAM lớn nhất.

7. Debug lỗi ứng dụng (namespace shop)

7.1 Quy trình chuẩn khi “web chết / API 502”

Xác định pod lỗi: kubectl get pods -n shop
Xem Events: kubectl describe pod <pod> -n shop | sed -n '/Events:/,$p'
Xem log hiện tại + log lần crash trước
Đối chiếu Grafana: OOM? CPU spike? Restart tăng?
Sửa / restart / rollback image
Logs 1 service (ví dụ auth)
POD=$(kubectl get pods -n shop -l app=auth-service -o jsonpath='{.items[0].metadata.name}')
kubectl logs "$POD" -n shop --tail=100
kubectl logs "$POD" -n shop --previous --tail=100   # lần crash trước
kubectl describe pod "$POD" -n shop | tail -40

# hoặc full scan
bash scripts/diagnose-apps.sh

7.2 Bảng lỗi thường gặp

STATUS / triệu chứngNguyên nhân hay gặpCách xử lý
CrashLoopBackOff App panic; sai env/secret; DB/Kafka down; migration thiếu Đọc logs + --previous. Kiểm tra infra. Chạy migrate. Fix config rồi rollout restart.
OOMKilled (Reason trong describe) Memory limit quá thấp / leak / seed quá lớn Grafana xem RAM. Tăng limits trong deployment. Tránh seed 60M trên VPS 16GB.
ImagePullBackOff / ErrImagePull Thiếu ghcr-secret; image private; sai tag bash scripts/setup-ghcr-pull-secret.sh. Kiểm tra image tag SHA trên GHCR.
CreateContainerConfigError Thiếu Secret/ConfigMap key kubectl describe pod → thiếu key nào → tạo/sửa secret.
Pending Không đủ CPU/RAM schedule; PVC Pending kubectl describe pod + kubectl top nodes + get pvc.
HTTP 502 / 504 qua Ingress Pod chưa Ready; service selector sai; probe fail kubectl get endpoints -n shop; readiness probe; logs gateway.
Login / JWT lỗi Redis down; auth CrashLoop; sai JWT key Kiểm tra redis + auth logs; so secret JWT public/private.
Upload avatar / MinIO lỗi MinIO down; sai bucket/policy; NetworkPolicy kubectl get pods -n infra -l app=minio; logs auth; secret MinIO.

9.3 Prometheus targets DOWN / không có metric shop

  • Mở Prometheus → Status → Targets.
  • NetworkPolicy: cần allow-monitoring-scrape.yaml để Prometheus scrape được shop/infra.
  • metrics-server (cho kubectl top) khác Prometheus — nếu kubectl top lỗi, cài/sửa metrics-server riêng.
kubectl apply -f k8s/base/monitoring/allow-monitoring-scrape.yaml
kubectl apply -f k8s/base/monitoring/allow-grafana-ingress.yaml

9.4 Monitoring làm VPS OOM

Stack đã tối ưu (Alertmanager tắt, retention 5 ngày, limit RAM Prometheus 1Gi). Nếu vẫn nặng:

  • Tạm scale down Grafana khi không dùng (không khuyến nghị lâu dài).
  • Giảm scrape interval / retention trong values-kube-prometheus.yaml rồi helm upgrade.
  • Ưu tiên tắt job seed / ES nặng trước.

10. Query PromQL hữu ích

Dán vào Grafana Explore hoặc Prometheus Graph.

Pod đang chạy / không chạy

kube_pod_status_phase{namespace="shop",phase="Running"} == 1
kube_pod_container_status_restarts_total{namespace="shop"}

RAM / CPU

# RAM đang dùng theo pod (bytes)
sum by (namespace, pod) (container_memory_working_set_bytes{namespace=~"shop|infra", container!=""})

# CPU cores
sum by (namespace, pod) (rate(container_cpu_usage_seconds_total{namespace=~"shop|infra", container!=""}[5m]))

# RAM node còn lại
node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes

OOMKill gần đây

increase(kube_pod_container_status_last_terminated_reason{reason="OOMKilled"}[6h])

Disk PVC

kubelet_volume_stats_used_bytes / kubelet_volume_stats_capacity_bytes

Target scrape

up

11. FAQ

Có cần build lại app để có monitoring không?

Không. Monitoring scrape metrics Kubernetes/node. App không bắt buộc expose /metrics (có thì tốt hơn cho business metrics).

Sau deploy-all.sh có mất Grafana không?

Không — monitoring nằm namespace riêng, cài bằng Helm. Chỉ mất nếu bạn xoá namespace monitoring.

Alert / Telegram / Email?

Hiện alertmanager.enabled: false để tiết kiệm RAM. Muốn bật: sửa values-kube-prometheus.yaml rồi helm upgrade, cấu hình receiver.
